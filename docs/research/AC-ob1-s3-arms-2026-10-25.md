## 0. The composed-fold env, resolved against AB's unit legs (the gap recorded verbatim)

The window spec named the fold's bank as `COLI_VK_TIER_BANK_LAYER=auto-if-exists-or-per-layer`. **No such
parse exists**: `COLI_VK_TIER_BANK_LAYER` takes an integer (the boot layer; `vk_tier.c:3067` `atoi`), and the
per-layer rotation itself is **code-driven, not env-driven** — `vkt_bank_switch(i)` at each layer head of the
layer-outer loop (`deepseek_v4_chain.h:1357`), no knob to arm. Per the instruction ("use what AB's unit legs
used at model scale; do NOT invent envs"), the fold ran **AB's unit-leg composed form with AA's K-validated
model-scale cap**:

```
COLI_VK_CHAIN_ORDER=layer COLI_VK_TIER_BANK_LAYER=1 COLI_VK_DMOE=all COLI_VK_DMOE_ROWS=1 COLI_VK_DMOE_ROWS_MAX=512
```

(the Makefile's composed brio leg: `ORDER=layer BANK=1 DMOE=all ROWS=1 ROWS_MAX=8` at tiny; `ROWS_MAX=512`
is AA's model-scale validation of the same knob, no device loss at bank scale). Gap verbatim: the
`auto-if-exists-or-per-layer` form does not exist; the integer boot layer (1) plus the code rotation is the
closest documented composed form, and it is what ran.

## 4. The fold's finding: the in-frame arm never opened at model scale (recorded, mechanism bounded)

The composed fold's dmoe half took **zero** steps in every rep. The only DMOE decline line in an F log belongs
to a decode-class forward (`COLI_VK_DMOE=all follows COLI_VK_CHAIN_ORDER=layer's prompt path (this forward is
not one it takes: decode, …)`, printed once, interleaved at the first decode step) — the **prefill's own** arm
call (one per forward, `deepseek_v4_chain.h:1635`) declined through a path that prints nothing. The two silent
candidates, bounded by the printed evidence and the code, not instrumented (a bench window changes no code):

1. **the tiny device reserve after the reservoir**: the arm's `gbias`/`lg` reserves (`deepseek_v4_chain.h:736`,
   1 KiB + 256 KiB, `VKC_DEV`) run right after the layer-outer reservoir took the 1.00 GiB the carve left
   (`xall`/`xd`/`list`/`cs` for a 2,515-row prompt) — a full device refuses them silently;
2. **the table-read turning the arm off**: `vkc_dmoe_read`'s `vkt_dev_table < 0` for any layer sets `d->off`
   (`vk_dmoe.h`, `vkc_dmoe_read`), which both fails prepare and suppresses v4c_dmoe_arm's decline print
   (`!ch->dm.off` in its guard).

Either way the gate is a **cold-start ordering gap at model scale**: the all-or-nothing prepare needs a layer
whole *at the forward's head*, the warm-start history tier never holds a layer whole (AA §2, N-arm), and the
bank only fills *during* the loop — so the arm that would compute in-frame from the banked residency cannot
open on the first (and only) layer-ordered forward. AB's tiny leg passed it because the fixture's tier holds
every expert resident from the start (the Makefile's own note). **What ran is therefore the full carve cost
plus the full rotation machinery with zero in-frame offset** — the measured F-fold is the coexistence wall AA
recorded, now *under* the reorder's rotation: the rotation itself is mechanically clean (43 tenures, at-most-once,
no thrash, ledger exact ×4) but it rotates a bank nothing computes from.

  rep ≥ every control rep) — an order/residency effect on the post-prefill tier state, not the layer-outer path
  (decode never takes it). Worth one look in S2's window; not a bar here.
